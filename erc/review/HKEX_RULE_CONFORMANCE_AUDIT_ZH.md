## 零、先说结论

| 编号 | 结论 | 级别 |
| --- | --- | --- |
| H-1 | **本标准缺了 HKEX 的核心机制:登记册封闭(book closure)。** HKEX 靠它让记录时刻在**事前**就确定;本标准只有**事后**终局(等到下一条条目出现)。 | 重大 |
| H-2 | 正文 Rationale 把这套机制归给了除权日(ex-date)。**归错了。** 除权日管的是交易侧,登记侧是封闭。 | 事实错误,已修 |
| H-3 | 有了封闭,不可回补权利的"永久消灭"从**常态**降为**兜底**。当前写法会让评审认为本标准例行销毁投票权。 | 重大(随 H-1) |
| H-4 | 本标准不需要除权日,这一点是优势,但正文没讲出来。 | 可加强 |
| H-5 | 每笔结算的 deadline 由发起方自选(上限 30 天),比 HKEX 的固定 T+2 松。作者此前明确要求"n 固定且不可撤销"。 | 中 |
| H-6 | HKEX 的封闭有法定累计上限(30+30 天/年),本标准对任何"冻结类"参数都没有累计约束。 | 中(随 H-1) |

## 一、HKEX 实际怎么做(逐条附出处)

| 事实 | 出处 |
| --- | --- |
| 发行人临时关闭过户登记册/股东名册,以确定有权参与公司行动的股东身份 | 《Guide on disclosure of record date, book closure and latest time for lodging transfers of shares》(2024-09 更新)§1.1 |
| **封闭期内不办理任何股份过户登记** | 同上 §1.1、§3.2 |
| 封闭须**提前公告**:一般情况至少 10 个营业日,供股至少 6 个营业日;变更封闭日期须在较早者之前至少 5 个营业日再公告 | 同上 §2.1(MB Rule 13.66(1) / GEM Rule 17.78(1)) |
| 记录日可落在封闭期内任何一天,**通常是最后一天**;通常以营业日结束时点取快照,否则须公告具体 `hh:mm` | 同上 §3.3(i) |
| 须公告**最后过户登记时间**,通常为某日下午 4:30 | 同上 §3.3(iii) |
| T+2 下,证券在**最后登记日的前一个营业日**除权交易;除权日及之后的买方不取得权益,除权日的卖方保留权益 | 同上 §2.4;《Guide on distribution of dividends and other entitlements》§2.2、§3.8(iv) |
| 官方举例:封闭 2008-09-01 至 09-26,最后过户登记时间为 08-29 营业结束,除权日为 08-28 | 封闭指引 §2.4 |
| 法定累计上限:登记册关闭全年合计不超过 30 天,经股东决议可再延 30 天 | 香港《公司条例》(Cap. 622)第 632 条 |
| **登记本身需要时间** —— HKEX 自己的原话:"share registration may take time to complete" | 封闭指引 §3.2 |
| 也可以不封闭,只设记录日,在记录日结束时对名册取快照 | 同上 §3.2 |
| 全程**不停牌**,证券照常交易,只是转为除权交易 | 上述各处 |
| CCASS 内的证券以 HKSCC Nominees Limited 为名册上的登记持有人,投资者持有的是实益权益 | HKSCC 相关文件 |

两点值得单独强调:

1. **HKEX 承认异步。** "share registration may take time to complete" 就写在官方指引里。本标准的前提和 HKEX 的前提是同一个。
2. **HKEX 从不为此停止交易。** 它停的是**登记**,不是**交易**。这正是本标准重写时采取的立场,方向一致。

## 二、H-1:缺了封闭机制

### HKEX 的终局性是事前的

封闭期一旦公告并开始,记录日的答案在那一刻就**不可能再变**了——因为封闭期内不会发生任何登记。股东、发行人、券商在投票开始之前就知道谁有权投票。

### 本标准的终局性是事后的

现行 `isFinalAsOf` 的判据是:

> t 已终局 ⟺ `第一条.effectiveAt ≤ t < 最新条目.effectiveAt`

也就是**必须等到下一条条目出现**,t 才终局。在此之前,一条 `effectiveAt` 更早的条目随时可能被准入并改写 t 的答案。

后果:一个按计划召开的投票,其记录时刻在投票开始时**几乎必然还没终局**(登记册通常不会恰好在那之前产生一条新条目)。于是按现行正文,这张票要么被永久消灭,要么就得靠运气等到一条新条目。**这不是 HKEX 的做法,也不是一个好标准该有的默认行为。**

### 封闭如何映射到本标准

HKEX 的"最后过户登记时间"才是关键闸门,不是封闭期本身。它的语义是:**过了这个时点,你再递交的过户在本轮里一律不生效。**

对应到本标准,一条规则就够:

> 封闭 `[a, b]`:一旦 `block.timestamp ≥ a`,其后准入的每一条条目 MUST 满足 `effectiveAt > b`。

由此立即得到:只要现在时间已过 `a`,任何 `t ≤ b` 都终局——未来条目的 `effectiveAt` 都大于 `b ≥ t`,不可能覆盖 t。

实现代价是**每个代币一个 `uint64`**(`sealedThrough`,单调递增)。终局判据变成:

> t 已终局 ⟺ `t ≥ 第一条.effectiveAt` 且(`t < 最新条目.effectiveAt` 或 `t ≤ sealedThrough`)

准入判据加一条:`effectiveAt > sealedThrough`。

### 这会不会丢失真实的登记变更

不会,而且这一点 HKEX 已经替我们验证过了。封闭期内递交的过户不是被丢弃,而是**待封闭结束后办理,自办理时生效,不回溯**。所以"条目的 `effectiveAt` 不得落在封闭区间内"并不是合约在篡改登记册,而是**如实反映一个遵守封闭规则的登记册本来就不会产生那样的生效时刻**。

若某个 Profile 的登记册不遵守自己宣告的封闭而产生了区间内的生效时刻,合约会拒绝该条目。这是登记册/Profile 违规,应在 Security Considerations 里写明,而不是默默接受。

### 必要的护栏(否则封闭会变成审查工具)

| 护栏 | 理由 | HKEX 对应 |
| --- | --- | --- |
| 封闭 MUST 在其开始前宣告(`a > block.timestamp`) | 否则可事后追封,把已经不利的答案冻住 | ≥10 营业日提前公告 |
| 封闭一旦开始 MUST NOT 修改或撤销 | 否则终局性可撤销,整个机制作废 | HKEX 只允许在开始前变更 |
| 单次封闭时长 MUST 有上限 | 否则等于永久冻结登记 | —— |
| 累计封闭时长 SHOULD 有上限 | 防止用高频短封闭实现长期冻结 | 法定 30+30 天/年 |
| `sealedThrough` 单调递增 | 保证终局不可逆 | 封闭不可回退 |

注意:这些护栏冻结的是**登记**,不是**交易**。代币在封闭期内照常转让,与本标准重写时确立的立场一致,也与 HKEX 一致。

## 三、H-2:正文的事实错误(已修)

原文(Rationale):

> Traditional infrastructure reaches the same result by centralising the arithmetic in an ex-date

**错。** 除权日解决的是交易侧:哪一笔成交带权。登记侧的确定性来自封闭。两者是配套的两半,而与本标准直接相关的是后者,恰恰是原文没提的那半。

这是我写的,不是从别处继承的。已改。

## 四、H-3:消灭规则应降为兜底

有了封闭,一次按计划进行的投票是这样的:

1. 发行人提前宣告封闭 `[a, b]`,记录时刻 `t ∈ [a, b]`;
2. 时间过 `a`,`t` 立刻终局;
3. `holderAsOf(t)` 给出唯一且不会再变的确认持有人;
4. 该持有人投票。**没有弃权,没有权利被消灭。**

只有在记录时刻**落在任何封闭之外**时——临时公司行动、登记册根本没有封闭纪律、或者封闭宣告晚了——才回到现行的两分法:可回补的递延,不可回补的双方均不可行使且永久消灭。

**这才是作者说的"比 HKEX 多考虑一点"的准确位置:HKEX 用日历设计让问题不发生;本标准既提供同样的日历设计,又在它失效时仍然给出一个确定的、双方都无法操纵的结果。** 现行正文只有后半截,读起来像是把销毁投票权当成常规做法,评审一定会打这一点。

## 五、H-4:本标准不需要除权日,这是优势

除权日是一个**补偿性**规则。HKEX 无法对一笔尚未交收的成交追问"在时刻 t 名册上是谁",它只能问"记录日名册上是谁";交收有 T+2 的滞后,于是必须反推出一个除权日,把滞后期内的成交标记为不带权,才能让名册在记录日的状态与经济上应有的归属对齐。

本标准不需要这一步:权利直接按**时刻**对投影解析,买方在记录时刻之后买入,他本来就不是该时刻的确认持有人。**滞后被如实记录,而不是被补偿掉。**

这句话应该写进 Rationale——它比现在那句错误的除权日类比强得多,而且是本标准相对传统基础设施的实质差别。

## 六、H-5:deadline 由发起方自选,比 HKEX 松

作者此前的要求:"标准的 n 是固定且不可撤销"。

现状:`settlementPeriod()` 返回**上限**(参考实现 30 天),每笔结算的 deadline 由发起方在上限内自选,且发起方可以反复用新结算顶替旧结算,从而不断延长缺口。

HKEX 的 T+2 是全市场常数,封闭期虽按次设定但须提前公告且受法定上限约束。

缓解程度:重写后缺口本身**不再影响交易,也不再影响终局性**,所以危害比旧设计小得多。但一个 Profile 若把 deadline 交给发起方自选,仍等于让一方单方面决定投影落后多久。建议正文加一句:Profile SHOULD 固定 deadline,而非交由发起方选择。

## 七、H-6:没有累计约束

若采纳 H-1,单次封闭上限必须有,累计上限建议以 SHOULD 写给 Profile(链上难以表达"每年"这样的日历概念,但 Profile 可以)。HKEX 的 30+30 天/年 是现成的参照。

## 八、核对结论

本标准与 HKEX 在**方向**上一致:承认登记异步、不为登记问题停止交易、权利按记录时刻对登记册解析。

差距集中在一点:**HKEX 有一个让记录时刻事前确定的机制,本标准没有。** 缺了它,本标准的默认行为(投票权被消灭)比 HKEX 差,而不是比 HKEX 强;补上它,作者所说的"多考虑一点"才真正成立——同样的日历设计,加上日历失效时的确定性兜底。
