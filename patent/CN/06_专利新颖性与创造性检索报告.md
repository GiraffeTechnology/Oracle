## 一、技术方案要点(检索的靶子)

权利要求 1 的技术特征可拆为七组:

| 编号 | 技术特征 |

## 四、逐特征对比

### 4.1 与 D1(最接近的专利文献)

D1 是本次检出的**主题最接近**的专利文献:链下证券登记簿与链上代币并存,由过户代理(transfer agent)协调二者。核对结果:

| 特征 | D1 是否公开 | 依据 |
| --- | --- | --- |
| F1 只增条目序列 | 部分。有 "append-only transfer records" 与 "perpetual storage" | 但记录的是转让流水,不构成按时刻可解析的持有区间 |
| F2 四项不变量 | **否** | 权项中无生效时刻单调性要求,亦无"承诺在通证内唯一"的约束 |
| F3 结算缺口与权限主体 | **否** | 无待定缺口对象,无独立于持有人的推进权 |
| F4 提交者不可信 + 字段全集绑定 | **否** | 依"cryptographic signatures 与对链的本地观察",未见对目的侧字段全集的绑定 |
| F5 加标签成员证明 / 远端状态根 | **否** | 全文未见 "state root"、"light client" 或等效表述 |
| F6 原子准入 | 未公开 | — |
| F7 过去时刻解析 + 终局判定 + 不阻断转让 | **否** | 只回答当前余额("balances ... determined based on observation of a blockchain network");链下手续被归为 non-routine transfer,按顺序处理,不存在"待定期间仍自由转让"的状态 |

**结论:D1 未公开 F2、F3、F4、F5、F7,新颖性不被 D1 破坏。**

> **重要限缩(依 `08_...` §2.2)**:"最接近的现有技术未公开"与"不属于公知常识"是两件事,审查员可以直接援引公知常识。补检索显示,F4 的"绑定目的链 ID 与合约地址"与 F5 的"消费标记、高度递增"在跨链桥安全领域属于公知常识。**因此 F4、F5 在创造性论证中应整体放弃主张**,全部创造性落在 F2 的严格递增、F7 的终局判定与不阻断转让,以及推进权与 `ownerOf` 的解耦这四条上。

### 4.2 与 D2(投影侧最接近的非专利文献)

D2 提供 `getPastVotes(account, timepoint)`,形式上接近 F7 的时刻查询。**但 D2 明文要求过去值不可变**:

> "For any integer that is strictly smaller than the current clock, the value returned by `getPastVotes` **SHOULD be constant** ... This function SHOULD only serve past checkpoints, which **SHOULD be immutable**."

D2 之所以能这么要求,是因为检查点由链自身写入、链即真值来源,不存在"后写条目落在先写条目之前"。**本申请的前提与之直接冲突**:被投影的登记册不受链控制,条目在其生效时刻**之后**才到达,过去时刻的答案在被后续条目闭合前是临时的。因此:

- F7 中的**终局性判定**在 D2 中是**空洞的**(过去永远不变,无需判定),在本申请中是必需的;
- F2 第三项(生效时刻严格递增)在 D2 中不存在对应约束,因为 D2 不需要处理迟到条目。

D2 与本申请不是可以叠加的两块,而是前提相反。**新颖性不被 D2 破坏,且 D2 不能与其他文献简单结合。**

### 4.3 与 D3、D8(证明侧)

D3 标准化跨链消息的证明式验证。其**广播语义要求一份证明服务多个接收方**,因此**刻意不**把证明绑定到目的侧字段集合,也不约束验证与执行之间的关系——这恰是 F4 与 F6 的反面。D3 证明一条消息被包含,不构造可按时刻解析的权属历史。

D8 用默克尔树认证链下数据以供链上脚本校验,与 F5 的成员证明部分重叠(属该领域常规手段)。核对其独立权利要求:F7 的过去时刻持有人查询——否;F2 的严格递增生效时刻——否(其"append-only"指区块链自身的块链接,不对交易的时序作要求);"终局性"——其所述终局为**区块确认意义上的不可逆**,与本申请"某过去时刻的答案不会再被后到条目覆盖"是**不同概念**;F7 的待定期间可转让——否(UTXO 非锁即解,无中间可交易态)。

### 4.4 与 D4、D5、D6、D7(登记/RWA 侧)

| 文献 | 核对结论 |
| --- | --- |
| D4 | 身份注册表**完全在链上**,校验的是**接收方资格**;不保存任何时间索引的持有历史,不建模链上链下之间的待定区间 |
| D5 | 用途最贴近(不动产 + 链下法律记录),以哈希承诺经营协议;但**明文假定**存在 "a trusted party tasked with ensuring the state of the on-chain property NFT accurately mirrors its physical counterpart",不建模滞后,不给出可核验机制 |
| D6 | **动机上最接近**:自述"handle operational delays ... **without requiring every user-facing event to immediately update the reserve registry**"。但其解法是给储备打一个 `PENDING` **状态标志**;`reserveOf`/`stateOf`/`quantityOf`/`allocatedQuantityOf` 等全部只答**当前**;实测 `asOf`、`isFinal` 出现 **0 次**;记录对象是**储备数量对金融工具的支撑**,不是**登记册在某时刻确认的持有人** |
| D7 | 凭可插拔验证器把链下实体标识映射到地址,证明侧形态相近;但自述"There is no function to transfer a registered identifier ... Changing the registrant requires **revoking and re-claiming**",即**只有当前态**,旧记录不构成可查询历史;实测 `asOf`、`isFinal` 出现 **0 次** |

### 4.5 与 D10、D11(公知技术)

D10 的叶/内节点标签化与 D11 的类型化摘要及域分隔均为公知技术。**本申请不就其本身主张新颖性**,它们出现在权利要求 1 的 S4-3、S4-4 与权利要求 10 中,作用是使 F4 的"绑定字段全集"与 F5 的"唯一成员路径"在实现层可靠成立。审查中若被指为公知,不影响 F2 + F7 的创造性论证。

## 五、结论

### 5.1 新颖性(《专利法》第二十二条第二款)

**成立。** 上述十一件对比文件中,没有任何一件公开了 F2 与 F7 的组合,即:

> 在链**不控制**登记册、条目**迟于其生效时刻**到达、过去答案**可被后到条目追改**的前提下,以"生效时刻严格递增 + 记录承诺在通证内唯一 + 区间由生效时刻闭合 + 只增不改"四项写入不变量,使任意过去时刻恰好解析出一个确认持有人,并使"该答案是否还会改变"退化为与最新条目生效时刻的一次比较。

> **提交前已补入说明书的一节(2026-09-04)**:说明书新增"三、关于本发明所施加的两项禁止:代价与由此换得的性质"([0024]–[0036]),逐项写明禁止追溯写入与禁止阻断转让各自的代价与换得的性质,并在 [0030] 论证"若不施加该禁止,终局性判据在原理上不存在";背景技术 [0009]–[0010] 记载双时态一族及其为何不能解决本问题;具体实施方式 [0083] 给出坐实该取舍的数值例子。**此前本报告的创造性论证只存在于本报告中,说明书没有对应记载——依《专利法》第三十三条,申请日之后无法补入,因此在提交前补上。**

### 5.2 创造性(《专利法》第二十二条第三款)

按"三步法":

**第一步,最接近的现有技术:D1。**

**第二步,区别技术特征与实际解决的技术问题。** 区别特征为 F2、F3、F4、F5、F7。这些特征实际解决的技术问题是:*在链外登记册异步更新、条目迟到的条件下,如何使链上对任意过去时刻的确认持有人给出唯一解,并使该解的可变性成为可判定的事实,同时不冻结通证转让、不依赖提交者诚实。*

**第三步,是否显而易见。** 判断为**非显而易见**,理由有三:

1. **最接近的时刻查询技术(D2)的技术教导与本申请的前提相反。** D2 之所以能提供过去时刻查询,前提是"过去值不可变";本申请恰恰处理"过去值可被追改"的情形。本领域技术人员由 D2 出发,得不到"用严格递增的生效时刻把终局性变成一次比较"的启示——在 D2 的世界里这个判定是不必要的。将 D2 与 D1 结合,只会得到"把链下过户流水写成检查点",仍然无法回答"这个答案还会不会变"。

2. **业界对同一问题给出的是另一种解法,构成反向教导。** D6 明确识别到链下操作延迟,但采取的是"打一个 `PENDING` 状态标志"这一自然而然的方案,其全部查询接口仍只答当前态。这说明面对同一技术问题,本领域的常规思路是**标注当前状态**,而不是**构造可按时刻解析且终局可判的历史**。

3. **F7 的"不阻断转让"与 F4 的"提交者不可信"在现有技术中被当作互斥项处理。** D1 把链下手续归为 non-routine transfer 顺序处理,D8 的 UTXO 非锁即解,通行工程做法是冻结。本申请通过把"可转让头寸"与"确认持有人"显式分开为两个并存的所有权概念(F7 末句:不由 `ownerOf` 推断持有人),同时取得二者,这一取舍不是常规选择。

### 5.3 客体适格性(《专利法》第二条第二款、第二十五条第一款第(二)项)

区块链类申请常因"属于智力活动的规则和方法"被驳。本申请的抗辩要点已写入说明书,此处列明供审查答复引用:

| 要件 | 本申请的对应 |
| --- | --- |
| **技术问题** | 链外登记册与链上通证异步导致:过去时刻的确认持有人不可唯一解析、答案可变性不可判定、规避手段须冻结转让、准入依赖单方报告不可核验(说明书 [0003]–[0009]) |
| **技术手段** | 密码学承诺链、生效时刻严格单调、通证内承诺唯一性约束、加标签默克尔成员证明与索引位耗尽、域分隔类型化摘要与门限签名验证、远端高度单调与证明消费标记、单事务原子写入(权项 S2、S4、S5;说明书 [0022]、[0066]–[0073]) |
