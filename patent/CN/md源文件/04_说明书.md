# 说 明 书

**发明名称:一种链下登记册向非同质化通证的投影方法和装置**

---

## 技术领域

[0001] 本发明涉及区块链数据处理技术领域,具体涉及一种将链外维护的权属登记册投影到区块链非同质化通证上、并使任意过去时刻的确认持有人唯一可解析、其终局性可判定的数据处理方法、装置、电子设备和计算机可读存储介质。

## 背景技术

[0002] 在以实物资产、不动产、证券、许可权等链外标的为对象的通证化应用中,标的的权属由一个链外登记册记载,而链上以非同质化通证(Non-Fungible Token,NFT)表示对该标的的可转让头寸。登记册的更新由登记方按其自身流程完成,与区块链的出块过程互不同步:一次链下过户完成登记的时刻,总是晚于其在登记册上被指定的生效时刻,也与链上通证转让的时刻不重合。

[0003] 该异步性带来四个尚未被现有技术解决的问题:

[0004] 其一,**过去时刻的确认持有人不可唯一解析**。链上仅有 `ownerOf` 一个所有权概念,它记录的是可转让头寸的当前归属,不是登记册确认的持有人。当某项权利的条款把权利人锚定在一个已经过去的记录时刻上时(例如按某一时刻的登记名册分配收益),链上无法回答"该时刻登记册确认的持有人是谁"。

[0005] 其二,**答案是否还会变不可判定**。即便某种实现把链下报告写到链上,由于登记册的条目在其生效时刻之后才到达链上,一条后到的条目可能携带一个更早的生效时刻,从而追改先前已经给出的答案。任何依赖该答案行事的第三方,无法判断自己拿到的是已经不会再变的答案,还是随时可能被覆盖的临时答案。

[0006] 其三,**现有规避手段以牺牲可用性为代价**。工程上通行的做法是在链下登记完成之前冻结通证转让。这既中止了一个本可继续运行的市场,又使得任何记录时刻落在冻结区间内的权利彻底无法行使;而且冻结方无法向与其没有任何关系的第三方场所说明冻结的原因与边界。

[0007] 其四,**依赖单方报告且不可被无关第三方核验**。登记册的内容通常不能公开(涉及个人身份信息、商业秘密,或不属于登记方可披露的范围),因此必然存在一个替登记册作出陈述的一方。现有做法把该陈述作为一次孤立的报告接受:它不与该来源此前的陈述发生任何绑定,不排除对同一时刻作出两次互相矛盾的陈述,事后也无法由无关第三方追问"在某时刻究竟被声称了什么"。

[0008] 现有的相关技术各自只触及上述问题的一部分:基于链上检查点的历史投票权查询技术(如以太坊 ERC-5805 与 ERC-6372)以链本身为真值来源,因而明确要求过去值不可变,其前提与链外登记册的异步到达直接冲突;基于证明的跨链消息验证技术(如 ERC-7965/ERC-7786)只证明单条消息被包含于某一远端状态,不构造可按时刻解析的权属历史;面向真实世界资产的通证化标准(如 ERC-3643)校验的是接收方资格,不保存时间索引的持有历史;以哈希承诺链下法律文件的方案(如 ERC-6065)则明文假定存在一个受信任方负责维持链上状态与链下标的一致;链上储备登记类方案(如 ERC-8332)虽已识别到链下操作存在延迟,但仅以一个 `PENDING` 状态标志加以标注,其全部查询接口只回答当前状态。

[0009] 因此,现有技术中缺少这样一种方案:在链不控制登记册、条目迟于其生效时刻到达、且过去答案可能被追改的前提下,仍使任意过去时刻恰好解析出一个确认持有人,并使该答案是否还会改变成为可判定的事实,同时全程不阻断通证转让,且条目的准入不依赖任何被信任的提交者。

## 发明内容

### 一、发明目的与要解决的技术问题

[0010] 本发明的目的在于提供一种链下登记册向非同质化通证的投影方法和装置,以解决背景技术中的四个技术问题,即:在链外登记册与链上通证异步的条件下,(1) 使任意过去时刻的确认持有人唯一可解析;(2) 使该答案的终局性可判定;(3) 使上述两点在不阻断通证转让的前提下达成;(4) 使条目的准入不依赖提交者的诚实,并使与登记方无关系的第三方能够独立核验。

### 二、技术方案

[0011] 本发明的核心技术构思是:登记册对自身作出的每一次变更,天然携带一个唯一的身份——该变更取得效力的时刻,以及该变更发生时登记册内容的承诺值。本发明把该身份转化为链上的一条只增的、可按时刻解析的条目序列,并以四项写入不变量约束该序列,使"某时刻的确认持有人"成为一个恰好有一个解的问题,同时使"该解是否还会变"退化为一次数值比较。

[0012] 具体地,本发明采用的技术方案包括以下方面。

[0013] **(一) 条目序列与四项写入不变量。** 合约为每个通证维护一条只增的登记条目序列。每条登记条目包含记录承诺、前序承诺、登记引用、持有人地址、版本号、生效时刻与被覆盖时刻。首条条目的版本号为 1 且前序承诺为零值。追加条目时施加四项不变量:①版本号为前一条加一,且前序承诺等于前一条的记录承诺;②将前一条的被覆盖时刻置为本条的生效时刻,本条的被覆盖时刻置零,即区间由登记册的生效时刻闭合,而不是由链上得知该变更的时刻闭合;③本条的生效时刻**严格大于**前一条的生效时刻;④本条的记录承诺在**同一通证**的序列内未曾出现。条目不得被覆写、删除、重排或跳号。

[0014] 不变量③与④是"唯一解"成立的最小条件:若允许两条条目共享同一生效时刻,则该时刻有两个答案;若允许承诺在同一通证内重复,则两条无法相互区分的条目无法被解析。

[0015] **(二) 终局性由一次比较判定。** 由不变量③直接可得:任何将来被准入的条目,其生效时刻必然严格大于当前最新条目的生效时刻,因而不可能覆盖任何已经早于最新条目生效时刻的时刻。于是,当且仅当给定时刻不早于首条条目的生效时刻、且严格早于最新条目的生效时刻时,该时刻为终局。位于最新条目生效时刻及其之后的时刻仍然可解析,但其解是临时的,可能被后到的条目覆盖。该判定为常数时间,且不依赖是否存在未闭合的缺口。

[0016] **(三) 结算缺口与争议时刻。** 合约为通证提供一个至多存在一个的"结算缺口",用以标示一次变更正在进行但尚未准入。开启缺口时校验:请求方为该通证的结算权限主体、结算标识非零且未被占用、起始快照承诺非零、截止时刻晚于当前区块时刻且其间隔不超过结算期上限。缺口记录其开启时刻。当某通证上存在一个开启时刻不晚于给定时刻的未闭合缺口时,该给定时刻被判定为**被争议**。被争议与非终局是两个不同的事实:前者说明此刻有一次变更正在飞行中,后者说明该时刻的答案在原理上仍可被覆盖。

[0017] **(四) 结算权限主体与 `ownerOf` 解耦并可读。** 谁有权推进投影(开启缺口),与谁持有可转让头寸,是两个不同的问题。本发明要求合约通过一个查询接口把前者暴露为第三方可读的事实,而不是隐含在实现内部;并且不由 `ownerOf` 派生该权限——若由 `ownerOf` 派生,则登记方将无法把自己已经完成的登记变更记入链上,而任意购得通证的一方将获得无限期挂起缺口的能力。

[0018] **(五) 凭远端终局状态的成员证明准入,提交者不可信。** 任意账户均可提交准入请求;合约不以请求方地址、中继白名单或任何账户签名作为验证依据。验证包括:①按预定类型化结构,由链标识、本合约地址、通证标识、结算标识、预期持有人、起始快照承诺、前序承诺、本次记录承诺、登记引用、下一版本号与生效时刻计算叶节点摘要——即证明被绑定到这一组字段的全集,任一字段被单独篡改都将使证明不成立;②以第一标签字节前缀计算叶节点、以不同于第一标签字节的第二标签字节前缀计算内部节点,沿成员路径逐层归并至根值,并在归并结束时要求路径索引的剩余位全为零,以排除同一根值下存在多组"(索引,兄弟节点)"均可通过的情形;③以包含链标识与合约地址的域分隔符,对包含远端登记册标识、远端高度、远端区块哈希、远端状态根与见证人集合承诺的类型化结构计算终局性摘要,并要求不少于门限数量、互不相同且属于见证人集合的地址可由签名恢复;④远端高度严格大于该通证已消费的最近远端高度;⑤由终局性摘要与叶节点摘要导出的证明标识未被消费。

[0019] **(六) 原子准入。** 上述验证全部通过时,于同一笔交易内原子地完成:标记证明标识已消费、更新最近远端高度、按不变量追加条目、闭合缺口并发出事件;任一步骤失败则回滚本次交易的全部效果,从而不存在"证明已被接受但投影尚未推进"的中间区间。

[0020] **(七) 转让不被阻断。** 缺口开启期间,通证依非同质化通证接口进行的普通转让不被阻断,`ownerOf` 立即变动;同时,合约不得由 `ownerOf` 推断确认持有人,也不得因普通转让而改变条目序列。投影只能经由前述凭证明的准入而改变。

[0021] **(八) 三个事实分别暴露。** 合约对外提供三项彼此独立的查询:给定时刻的确认持有人;该时刻是否终局;该时刻是否被争议。三者不被合并为一个返回值,因为不同的权利条款需要其中不同的项:一项针对过去记录时刻主张的权利需要前两项;一项发生在当下且不可重复的行使无法等待终局(当下时刻永远不终局),它能够看到的是第三项。本发明只提供这三项事实,不规定任何权利在拿到这三项事实后应当如何处置——该处置由权利自身的条款决定。

### 三、有益效果

[0022] 与现有技术相比,本发明具有以下有益效果:

[0023] (1) **任意过去时刻恰好解析出一个确认持有人。** 由不变量①至④共同保证,在链不控制登记册、条目迟到的前提下仍然成立,而无需假设链是真值来源。

[0024] (2) **终局性可判定且为常数时间。** 判定退化为与最新条目生效时刻的一次比较,不需遍历历史,也不需等待任何超时。相较于现有以"当前状态标志"标注链下延迟的方案,本发明给出的是一个可被无关第三方独立复算的判据。

[0025] (3) **不牺牲市场可用性。** 通证在整个待定区间内继续转让,不存在冻结;记录时刻落在待定区间内的权利仍然可以被解析到唯一的确认持有人。

[0026] (4) **提交者不可信,准入不可被单方伪造。** 由于证明绑定到链标识、合约地址、通证标识、结算标识、持有人、起始快照、前后承诺、版本号与生效时刻的全集,并需通过门限见证与成员证明,任何单个提交者无法伪造或改写一次准入;由于远端高度严格递增与证明消费标记,一份证明无法被重放。

[0027] (5) **矛盾被留痕而非被覆盖。** 由于条目只增且承诺在通证内唯一,一个自相矛盾的来源会把矛盾留在记录上,而不是把先前的陈述抹掉;与登记方没有任何关系的第三方可以在事后看到这一点。

[0028] (6) **登记册内容不上链。** 链上只承载承诺值与登记引用,不承载记录本身,因而适用于内容不宜或不能公开的登记册;有权读取登记册的一方可凭登记引用定位该承诺所承诺的记录。

[0029] 需要说明的是,本发明并不消除"必须有一方替登记册作出陈述"这一事实——不能上链的数据必然由能够看到它的一方来断言;本发明改变的是该断言被赋予的自由度:断言进入每个通证唯一的只增顺序,两条断言不能共享一个生效时刻,任何一条不能被重放,任意过去时刻都可以在很久以后被重新检查。

## 具体实施方式

[0034] 下面结合附图对本发明的具体实施方式作进一步说明。所述实施例用于解释本发明,而非限定本发明的保护范围。

### 实施例一:系统结构

[0035] 参见图 1,本实施例的系统包括:

[0036] **链下登记册 (110)**,为记载标的权属的外部台账,其更新相对于区块链是异步的。其内容不上链。

[0037] **见证方集合 (120)**,由若干持有私钥的见证人组成,对登记册在某一远端高度上的终局状态(远端状态根)作出签名断言。见证方可以是远端链的轻客户端、一组签名人、登记方自身的密钥,或一段在登记册上运行的确定性程序;本发明不约束该断言值是如何得出的,只要求对该断言的**校验**是确定性的且经过域分隔。见证人集合与门限数量由验证配置 (140) 固定。

[0038] **提交人 (130)**,为任意账户,负责把证明数据搬运到链上。提交人**不被信任**:合约不以其地址、白名单或签名作为验证依据。

[0039] **链上合约 (150)**,同时实现非同质化通证接口与本发明的两组接口,内部包含:条目存储模块 (151)、不变量校验模块 (152)、缺口管理模块 (153)、证明验证模块 (154)、时刻解析与终局判定模块 (155)。

[0040] **验证配置 (140)**,即验证配置标识所指代的一组规则,包括远端终局性证明规则、轻客户端或见证人集合规则、状态根承诺方式、成员证明算法、见证人集合演化方式、规范化编码与哈希函数。合约以一个非零且不可变的标识对外声明它接受哪一套规则。

[0041] **第三方消费方 (160)**,例如交易场所、钱包、索引服务、抵押系统或收益分配合约,与登记方之间没有任何关系,只通过合约的公开查询接口获取事实。

### 实施例二:数据结构

[0042] 登记条目结构体的一种实现形式如下(以 Solidity 语法示例,不构成对实现语言的限定):

```solidity
struct RegisterEntry {
    bytes32 recordCommitment;    // 记录承诺,非零
    bytes32 previousCommitment;  // 前序承诺,首条为零
    bytes32 registryReference;   // 登记引用,合约不解释其含义
    address holder;              // 该条目确认的持有人
    uint64  version;             // 版本号,首条为 1
    uint64  effectiveAt;         // 生效时刻
    uint64  supersededAt;        // 被覆盖时刻,最新条目为 0
}
```

[0043] 结算记录结构体的一种实现形式如下:

```solidity
enum GapStatus { NONE, OPEN, ADMITTED, CANCELLED, SUPERSEDED }

struct Settlement {
    uint256    tokenId;
    address    initiator;
    address    expectedHolder;
    bytes32    snapshotHash;   // 起始快照承诺,非零
    uint64     openedAt;       // 开启时刻,取自区块时间戳
    uint64     deadline;       // 截止时刻
    GapStatus  status;
}
```

[0044] 上述各时刻均为自 Unix 纪元起的秒计数,与区块时间戳同一尺度。登记册的时刻与链上的时刻因此可以直接比较,这是"被争议时刻"判定得以成立的前提。若某登记册的生效时刻无法表达在该尺度上,则其不适用本发明的接口。

[0045] **登记引用**是登记册对该条目自身记录的定位符。合约从不解释它;有权读取登记册的一方凭它找到该承诺所承诺的那条记录,而持有人的身份信息即存在于该记录中。链上承载的是引用,而不是身份信息本身。

[0046] **起始快照承诺**把一次结算钉在一个起点上,使得为某一起点开启的结算所产生的证明,不能被准入到一个从不同起点开启的结算中。

### 实施例三:开启结算缺口

[0047] 参见图 3 与图 4 的步骤 S410。缺口管理模块 (153) 收到开启请求后依次校验:

[0048] (a) 通证存在;(b) 请求方满足结算权限主体查询接口的判定;(c) 结算标识非零且当前未被占用;(d) 起始快照承诺非零;(e) 预期持有人地址非零;(f) 截止时刻严格晚于当前区块时间戳;(g) 截止时刻与当前区块时间戳之差不超过结算期上限。

[0049] 校验通过后,若该通证上已存在一个未闭合缺口,则将该旧缺口置为"已被覆盖"并发出相应事件,且**不改变条目序列**;随后写入新的结算记录,状态置为"开启",开启时刻取当前区块时间戳,并把该通证的未闭合缺口指向新的结算标识。

[0050] 预期持有人等于当前确认持有人是被**允许**的,由此准入的条目称为**确认性条目**,其含义为"截至更晚的一个生效时刻,登记册记载的仍是同一持有人"。确认性条目是持有人长期不变的通证上"较早时刻得以变为终局"的唯一途径:若不允许确认性条目,则最新条目生效时刻及其之后的时刻将永远不会终局,任何等待终局的处理将无限期等待。

### 实施例四:凭证明的准入

[0051] 参见图 4 的步骤 S420 至 S460。证明验证模块 (154) 的处理如下。

[0052] **S420 前置校验。** 缺口状态为"开启";当前区块时间戳不晚于该缺口的截止时刻;记录承诺非零;本次生效时刻严格大于前一条条目的生效时刻;本次生效时刻不超过当前区块时间戳加上前向上界;本次记录承诺在该通证内未被使用过。

[0053] 其中前向上界的设置理由是:由于生效时刻严格递增,一个远超当前时刻的生效时刻一旦被准入,此后不可能有任何条目超过它,该通证的投影将被永久终止;故实现应当拒绝超出其配置所允许范围的生效时刻。

[0054] **S430 计算叶节点摘要。** 按预定的类型化结构对下列字段整体计算摘要:当前链标识、本合约地址、通证标识、结算标识、缺口中记录的预期持有人、缺口中记录的起始快照承诺、前一条条目的记录承诺、本次记录承诺、登记引用、下一版本号、本次生效时刻。任一字段被单独改动,所得叶节点摘要即不同,成员证明随之不成立。一种实现形式为:

```solidity
bytes32 leafStruct = keccak256(abi.encode(
    REMOTE_ENTRY_LEAF_TYPEHASH,
    block.chainid, address(this), tokenId, settlementId,
    expectedHolder, snapshotHash,
    previousCommitment, recordCommitment, registryReference,
    nextVersion, effectiveAt
));
bytes32 leaf = keccak256(abi.encodePacked(LEAF_TAG, leafStruct));
```

[0055] **S440 成员证明校验。** 以第一标签字节(例如 `0x00`)前缀计算叶节点,以不同于第一标签字节的第二标签字节(例如 `0x01`)前缀计算内部节点,按路径索引的最低位决定左右次序逐层归并;归并结束后,要求路径索引的剩余位全部为零,并且归并所得的根值等于证明数据中的远端状态根。索引位耗尽这一条件用于排除同一根值下存在多组"(索引,兄弟节点序列)"均能通过的情形。

[0056] **S450 终局性校验。** 构造包含名称、版本、链标识与本合约地址的域分隔符,对包含远端登记册标识、远端高度、远端区块哈希、远端状态根与见证人集合承诺的类型化结构计算终局性摘要;要求签名数量不少于门限值,且逐一恢复出的签名人地址均属于见证人集合、并按地址严格递增排列(从而同一签名人不被重复计数);签名的 s 值应位于低半区间以排除延展性。域分隔使得为一条链、一份合约产生的签名不能被搬到另一条链或另一份合约上使用。

[0057] **S460 高度与重放校验。** 要求本次远端高度严格大于该通证已消费的最近远端高度;由终局性摘要与叶节点摘要导出证明标识,要求其未被消费过。

[0058] **S470 原子写入。** 在同一笔交易内依次完成:标记证明标识已消费、更新该通证的最近远端高度、把前一条条目的被覆盖时刻置为本次生效时刻、标记本次记录承诺已在该通证内使用、追加新条目、把缺口状态置为"已准入"、清除该通证的未闭合缺口指向,并发出条目覆盖事件与结算完成事件。任一步骤失败则整笔交易回滚。

### 实施例五:取消与覆盖

[0059] 缺口的发起方可以取消一个开启中的缺口,但**只能在截止时刻之后**。截止时刻之前的取消请求被拒绝,其理由是:截止时刻之前的窗口属于证明——若允许提前取消,发起方可以单方面把一条登记册已经在远端完成的记录悬置,使该区间的投影永久不可解析。取消不改变条目序列:先前的条目继续有效,因而临时答案回落到缺口开启前被确认的持有人,但该时刻并不因此变为终局——登记册已经作出、而本链尚未看到的变更,此后仍可被准入。

[0060] 在一个通证上开启新的结算会覆盖旧的结算。被覆盖的结算不能再被完成,因而为它已经产生的证明随之作废。该性质既是可用性手段(允许纠正一次错误开启),也是一种权力:能够开启结算的一方可以借由不断覆盖而无限期地把缺口挂起,使全部近期时刻保持非终局且被争议。此时投影并没有作出任何错误陈述——它恰好陈述了"答案未定"——但它停止跟踪其登记册。因此实现应当对可覆盖的主体或时机加以限制,并且不应由 `ownerOf` 派生该权限,否则该挂起能力将随每一次转让被重新授予任意购得通证的一方。

### 实施例六:查询与消费

[0061] 参见图 2。时刻解析与终局判定模块 (155) 提供:

[0062] (a) **按时刻取条目**:返回生效区间覆盖给定时刻的条目;给定时刻早于首条条目生效时刻时报错回退;

[0063] (b) **按时刻取持有人**:返回上述条目的持有人;

[0064] (c) **终局判定**:当且仅当给定时刻不早于首条条目的生效时刻、且严格早于最新条目的生效时刻时返回真;其余情形返回假;对早于首条条目的时刻返回假而**不**回退,以便消费方可以先问终局性再决定是否解析;

[0065] (d) **未闭合缺口查询**:返回该通证上未闭合缺口的标识,不存在时返回零值;结合缺口的开启时刻即可判定给定时刻是否被争议。

[0066] 第三方消费方 (160) 的典型用法是:一项针对已过去的记录时刻主张的权利,先以 (c) 判定该时刻是否终局,再以 (b) 取得该时刻的确认持有人;一项发生在当下且不可重复的行使,由于当下时刻位于最新条目生效时刻及其之后而永远不终局,它转而以 (d) 判定当下是否被争议。本发明只提供这三项事实,其后的处置由权利自身的条款决定。

[0067] 一个已经完成的行使,不受此后被准入的条目的影响:本发明界定的是登记册的答案何时改变,而不赋予后来的答案以推翻既已依照先前答案作出的行为的效力。

### 关于安全性的补充说明

[0071] 本发明去除的是对提交人的信任,而非全部信任。其安全性仍依赖于远端共识、轻客户端或见证人门限、见证人集合更新规则、密码学原语、规范化编码、验证器实现及任何升级权限。一个串通的远端共识可以对一条虚假记录给出终局性,一个有缺陷的验证器可以接受一份无效证明。一份证明所证成的是"某段字节被包含于被接受的、已终局的远端状态之中",它并不证成该标的存在、登记方陈述属实,或该记录具有法律效力。

[0072] 由于投影的推进依赖于后续条目的存在,一个停止产生条目的登记册将使近期时刻永久非终局。这是对登记册及其验证配置的活性依赖,而非安全性缺陷;但一个不提供确认性条目产生途径的验证配置将继承该依赖。

[0073] 条目、承诺、参与者、时刻与证明材料均为公开数据。承诺可能因输入熵值过低或相关性分析而泄露信息,故验证配置宜采用经域分隔的承诺、避免承诺明文中的机密内容,并只公布验证所必需的证明材料。删除链下数据并不能删除链上的承诺、日志、调用数据与历史状态。
