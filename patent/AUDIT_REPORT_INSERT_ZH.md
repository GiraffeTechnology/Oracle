## 3.D6(新增发布阻断项):专利申请日与 ERC 公开日的顺序不可逆

**这是本次审计新增的唯一阻断项,且它是 D 类里唯一一条有明确失效时点的。**

| 项 | 内容 |
| --- | --- |
| 阻断内容 | 本专利申请的申请日**必须早于**下列任一动作:向 `ethereum/ERCs` 提交提案 PR、在 Ethereum Magicians 论坛发帖、以 CC0 公开参考实现 |
| 依据 | 《专利法》第二十二条(现有技术)。三者均不属于第二十四条列举的三种可主张宽限期的情形——**GitHub 提交与论坛发帖不是"规定的学术会议或技术会议"** |
| 后果 | 任一动作先行发生,本申请即失去新颖性,**且不可挽回** |
| 当前是否可控 | **是**。`erc/review/PREP_READY_LEDGER_V9.json` 记 `discussionPublished: false`、`pullRequestCreated: false` |
| 谁能关闭 | 法务 / 申请人(决定是否申请、何时申请),**工程无法关闭** |

**与既有阻断项的相互作用**:PRD §14 的既有 5 项阻断项(D1–D5)不设失效时点,拖延只是拖延;
D6 不同——ERC 提交流程一旦推进到发帖取 `discussions-to` 链接这一步,D6 即刻失效。因此
**§5 优先级表中"并行启动,不要串行等待"的原则对 D6 不适用**:D6 必须先于 ERC 公开动作完成,
或者由申请人明确决定放弃专利。二者取其一,不能都推迟。

另有一项**须法务与申请人决定、本文件不代为决定**的事项:ERC 以 CC0 发布,放弃的是著作权及
邻接权,通常不被解释为专利许可;但 EIP 流程要求作者披露相关专利,且部分实施者预期标准必要
专利以 RAND 或免费条件许可。**若既要持有专利又要推进标准,须事先决定并公开声明许可立场**,
否则将在提案讨论阶段被质询。
