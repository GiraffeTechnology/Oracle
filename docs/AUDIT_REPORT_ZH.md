#### D6（新增阻断项）：专利申请日与 ERC 公开日的顺序不可逆

**这是 D 类里唯一一条有明确失效时点的阻断项。**

| 项 | 内容 |
| --- | --- |
| 阻断内容 | 专利申请的申请日**必须早于**下列任一动作：向 `ethereum/ERCs` 提交提案 PR、在 Ethereum Magicians 论坛发帖、以 CC0 公开参考实现 |
| 依据 | 《专利法》第二十二条（现有技术）。三者均不属于第二十四条列举的可主张宽限期情形——**GitHub 提交与论坛发帖不是「规定的学术会议或技术会议」** |
| 后果 | 任一动作先行发生，申请即失去新颖性，**且不可挽回** |
| 当前是否可控 | **是**。`erc/review/PREP_READY_LEDGER_V9.json` 记 `discussionPublished: false`、`pullRequestCreated: false` |
| 谁能关闭 | 法务 / 申请人（决定是否申请、何时申请），**工程无法关闭** |

**与既有阻断项的相互作用，以及本报告 §5 的一处失效**：D1–D5 不设失效时点，拖延只是拖延；
D6 不同——ERC 提交流程一旦推进到「发帖取 `discussions-to` 链接」这一步，D6 即刻失效。

因此 **§5「并行启动，不要串行等待」的原则对 D6 不适用**。D6 必须先于任何 ERC 公开动作完成，
或由申请人明确决定放弃专利；**二者取其一，不能都推迟**。

> **本报告初版的一处危险表述**：§3 C 类与关联 issue 曾把「发 Ethereum Magicians 帖取
> `discussions-to` 链接」列为 ERC 侧「剩余唯一阻断项」并建议尽快推进。在 D6 存在的前提下，
> **那样做会不可挽回地毁掉专利新颖性**。该建议已作废，顺序以 D6 为准。

另有一项须法务与申请人决定、工程不代为决定：ERC 以 CC0 发布放弃的是著作权及邻接权，通常
不被解释为专利许可；但 EIP 流程要求作者披露相关专利，部分实施者预期标准必要专利以 RAND 或
免费条件许可。**若既持有专利又推进标准，须事先决定并公开声明许可立场**，否则会在提案讨论
阶段被质询。

### 4.2 ERC 的 PR 编号不可作为标识

一天之内换了三次：#3 → #13 → #16，**每次都是关闭后数十秒内以同一 head 重开**。
**「PR 已关闭」不代表工作停止**——三次关闭时分支都在继续推进。仓库内所有引用已改为分支名，
PR 编号仅作「当前视图」记录。

**2026-09-04 更新**：轮换已停止。序列为 #3 → #13 → #16 → **#18**，PR #18 正文声明
「**#18 不再轮换**」。分支仍是权威标识，但 #18 现在是稳定视图，可以引用。

### 4.3 重锚规则

原按分支 head 重锚，一个会话内重锚四次，其中一次（`a5270ad`→`bdea8e0`）只改了内部审查台账，
规范一字未动。已改为**按 `erc/ERCS/erc-xxxx.md` 变化触发重锚**，锚定含义明确为「四项属性最后
一次被核验时所处的 commit」，不是对分支 head 的断言。
