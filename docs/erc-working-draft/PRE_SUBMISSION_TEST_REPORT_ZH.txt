SettlementAuthorization(uint256 tokenId,bytes32 settlementId,address from,address to,bytes32 previousCertificateHash,bytes32 newCertificateHash,uint64 newCertificateVersion,uint64 effectiveAt,uint64 validUntil,uint256 nonce)

完整合规实现必须同时实现两个拟议接口，并实现 ERC-8325 IAssetBoundTokenId；只实现只读证书接口不得宣称符合本提案。

三、ERC 参考实现测试

结果：17 passing，0 failing；Solidity 编译错误 0，警告 0。

已验证：

1. 三个接口 ID 均由函数 selector 逐项 XOR 确认；
2. 两个拟议接口不存在 selector 冲突；
3. supportsInterface 对 ERC-165、ERC-721、两个拟议接口和 ERC-8325 返回 true，对 0xffffffff 返回 false；
4. 参考实现运行时代码低于 EIP-170 的 24,576-byte 上限；
5. 一个 tokenId 只有一个非零、不可变的 ERC-8325 anchorId，anchorRegistry 不可变；
6. anchor 不活跃时 beginSettlement 失败；
7. 初始证书版本为 1，历史为追加式，连续多轮 T+n 交割不跳号、不覆盖；
8. Pending 期间 ownerOf 保持 from，transferFrom 和两个 safeTransferFrom 重载全部失败；
9. approved operator 不能绕过 Pending；
10. 正确最终确认原子更新证书、持有人、nonce 和交割状态；
11. 错误签名、过期授权、超期确认及 nonce 跨 Token 重放均被拒绝，失败不留下部分状态；
12. authorityData 可以按规范 tuple 解码，解码值与签名字段一致；
13. deadline 后 from 可用空 authorityData 取消；
14. deadline 前可由 Authority 使用 CancellationAuthorization 取消；
15. finalize 与 cancel 共用 Authority nonce 防重放空间；
16. EOA 使用低 s ECDSA 验证；合约 Authority 使用 ERC-1271 验证；
17. 三个最终确认事件均存在；测试不再把事件顺序当作有效性的必要条件。
